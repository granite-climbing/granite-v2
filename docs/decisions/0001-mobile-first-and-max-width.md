title: 모바일 전용 렌더링과 데스크톱 max-width 480

## Context

Granite v2의 핵심 사용 시나리오(스팟 탐색, 베타 캡션 복사 → IG 공유, 현장에서 접근법 확인)는 거의 전부 모바일에서 발생한다. 데스크톱 전용 화면을 별도로 만들면 디자인·QA 비용이 두 배가 되고, 초기 출시 일정에 부담이 크다.

## Decision

전 화면을 모바일 디자인 기준으로 구현하고, 데스크톱 브라우저에서는 `max-width: 480px` 컨테이너로 중앙 정렬해서 동일 화면을 렌더한다. 좌우 여백은 회색 패딩. 별도 데스크톱 분기 디자인은 두지 않는다.

## Consequences

- 디자인/QA가 단일 폼팩터로 수렴 → 출시 일정 단축.
- 데스크톱 사용자 경험은 "스마트폰을 큰 모니터에 띄운 느낌"이 됨. SEO 메타데이터·OG 이미지로 정보 접근성만 확보한다.
- 향후 데스크톱 전용 관리자 화면이 필요해지면 `/admin/*`만 별도 폼팩터로 분기할 수 있다 (이 ADR의 범위 밖).

## Alternatives considered

- **반응형 풀 디자인**: Figma 2종 + QA 2종 부담. MVP 단계에서 ROI 낮음.
- **데스크톱 차단/리다이렉트**: 검색 유입과 공유 링크 클릭률을 떨어뜨림.
